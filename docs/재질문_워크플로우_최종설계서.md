# 재질문(Clarification) 워크플로우 — 최종 설계서

> 프로젝트: 영화 관련 질문 답변 Agentic RAG 서비스
> 목적: 사용자의 모호한 질문을, 무거운 검색·답변 파이프라인에 들어가기 전에 감지하고, 선택지형 재질문으로 의도를 확정한 뒤 명확한 질문을 뒤 단계로 전달한다.
> 기반 논문: ① Zhang & Choi, "Clarify When Necessary" (2023) — INTENT-SIM / ② Lee et al., "CAmbigNQ" (EMNLP 2023 Findings) — 선택지형 CQ 형식 / ③ Kuhn et al., "CLAM" (2022) — 파이프라인 구조와 자동 평가
> 사용 모델: gpt-4o-mini (전 단계 통일, 병목 확인 후 역할별 분리 검토)

---

## 1. 설계 목표와 원칙

이 워크플로우는 세 가지 원칙 위에 서 있다.

**원칙 1 — 판단을 모델에게 맡기지 않는다.** "모호하면 되물어라"라는 지시 한 줄로는 모델이 거의 되묻지 않는다는 것이 CLAM 실험으로 확인되었다(지시만: 37.5점 vs 구조화: 54.4점). 따라서 되물을지 말지의 결정은 모델의 생성 관성이 아니라, 엔트로피 점수와 임계값을 비교하는 코드가 내린다. 모델은 각 단계에서 좁게 정의된 일(샘플 생성, 문장 다듬기, 재작성)만 수행한다.

**원칙 2 — 무거운 것은 뒤로.** 답변 1회가 (검색 + LLM 호출) × 노드 수 × hop 수인 Agentic RAG에서, 판정은 답변 파이프라인을 전혀 건드리지 않고 노드 안에서 끝나야 한다. 이 워크플로우의 판정 비용은 짧은 LLM 호출 약 10회 + 임베딩 계산뿐이며, 명확한 질문은 추가 비용 거의 0으로 통과한다.

**원칙 3 — 계산을 재활용한다.** 판정 과정에서 만들어지는 부산물(의도 클러스터)이 그대로 재질문의 선택지가 된다. 판정용 계산과 생성용 계산을 따로 하지 않는다.

## 2. 전체 파이프라인 한눈에 보기

```
사용자 질문 x
  │
  ▼
[0단계] DB 메타데이터 조회 (제목/인물 필드 정확 매칭)
  │
  ▼
[1단계] 의도 직접 샘플링 — "이 질문을 한 서로 다른 사용자들의
        의도"를 LLM으로 10개 생성 (온도 0.5, 검증셋으로 튜닝)
  │
  ▼
[2단계] 같은 뜻 판정 — 의도 쌍마다 임베딩 유사도로 동치 판정
        → 같은 뜻이면 선(간선) 긋기 → 그래프 완성
  │
  ▼
[3단계] DFS로 연결 요소 찾기 = 클러스터
        (선을 타고 이어진 덩어리 하나 = 서로 다른 해석 하나)
  │
  ▼
[4단계] 엔트로피 계산 — 클러스터 크기 비율 분포의 엔트로피 u(x)
  │
  ▼
[5단계] 판정 분기
        u(x) ≤ τ 그리고 DB 매칭 ≤ 1건  → x 그대로 통과 (노드 종료)
        u(x) > τ 또는 DB 매칭 ≥ 2건    → 재질문 진행 ▼
  │
  ▼
[6단계] 선택지 조립 — 클러스터 대표(소스 A) + DB 매칭 항목(소스 B)
        병합 → 환각 검증 → "어느 [카테고리]: ①②③?" 형식으로 포장
  │
  ▼
[7단계] 사용자 제시 (interrupt) — 선택지 + "다른 의도면 직접 입력"
        폴백 → 사용자 응답 수신 (resume)
  │
  ▼
[8단계] 최종 질문 재구성 — x + 사용자 선택/입력을 합쳐
        자연스러운 한 문장으로 재작성 → 다음 노드로 전달
```

## 3. 단계별 상세 설명

### 0단계 — DB 메타데이터 조회

사용자 질문에 포함된 제목·인물 키워드로 영화 DB의 메타데이터 필드를 정확 매칭 조회한다(상위 5건). 임베딩 기반 의미 검색이 아니라 필드 조회라는 점이 중요하다. 모호한 질문으로 의미 검색을 하면 여러 해석의 결과가 뒤섞인 잡음이 나오지만, "제목 필드에 '베테랑'이 몇 건 매칭되는가"는 질문이 모호해도 신뢰할 수 있는 조회이기 때문이다.

이 단계의 역할은 두 가지다. 첫째, 동명작·시리즈 모호함의 확실한 단서를 확보한다("베테랑" → 2015년작과 2024년작 2건 매칭). 둘째, 6단계에서 선택지의 정확한 재료(연도, 감독 등 메타데이터)가 된다.

```
예시:
"베테랑 줄거리 알려줘"  → 매칭: [베테랑(2015, 류승완), 베테랑2(2024, 류승완)]
"학생 영화 추천해줘"    → 매칭: 없음 (동명작 아님 — 이 유형은 1단계가 담당)
"극한직업 줄거리"       → 매칭: [극한직업(2019)] 1건
```

### 1단계 — 의도 직접 샘플링

LLM에게 "이 질문을 한 서로 다른 사용자 한 명을 상상하고, 그 사용자의 구체적인 의도를 한 문장으로 써라"라는 프롬프트를 온도 0.5로 10회 독립 실행한다. LLM은 방대한 사람 글로 학습되어 "사람들이 이 말을 어떤 뜻으로 쓰는가"에 대한 통계적 감각을 갖고 있으므로, 샘플링은 그 감각에서 실제 의도 분포의 근사 샘플을 뽑아내는 행위다.

```
"학생 영화 추천해줘"의 샘플 예:
  s1: "학생이 주인공으로 나오는 영화를 원한다"
  s2: "고등학생 자녀와 함께 볼 수 있는 등급의 영화를 원한다"
  s3: "학교를 배경으로 한 청춘물을 원한다"
  s4: "학생이 주인공인 성장 영화를 원한다"
  ... (총 10개)
```

온도는 하이퍼파라미터다. 너무 낮으면 다수 해석 하나로만 수렴해 소수 해석을 놓치고(누락), 너무 높으면 명확한 질문에서도 억지 해석이 튀어나와 명확/모호의 구분력이 흐려진다. 검증셋에서 온도 {0.5, 0.7}의 AUROC를 비교해 확정한다. 수렴이 심하면 대안으로 "서로 구별되는 의도 5가지를 나열하라" 프롬프트 1회 방식(다양성을 온도가 아니라 지시로 확보)으로 전환한다.

### 2단계 — 같은 뜻 판정 (동치 그래프 구성)

의도 샘플 10개에서 2개씩 뽑는 모든 쌍(최대 45쌍)에 대해 "같은 뜻인가"를 판정하고, 같으면 두 샘플 사이에 선(간선)을 긋는다. 판정기는 한국어 문장 임베딩의 코사인 유사도 + 임계값(초기값 0.85, 검증셋으로 조정)을 사용한다.

모든 쌍이 직접 연결될 필요는 없다. s2("등급 영화")와 s4("성장 영화")가 직접 판정에서 애매하더라도, 각각 s1과 연결되어 있으면 다음 단계에서 간접적으로 한 덩어리가 된다.

### 3단계 — DFS 연결 요소 찾기 = 클러스터링

2단계에서 만든 그래프에서 "서로 이어진 덩어리(연결 요소)"를 DFS로 찾는다. 잉크 번지기에 비유하면: 색칠 안 된 점 하나에 잉크를 떨어뜨리면 선을 타고 이어진 점들로만 번지고, 번짐이 멈추면 물든 점들이 덩어리 하나다. 색칠 안 된 점이 없어질 때까지 새 색으로 반복한다. 별도의 클러스터링 알고리즘이 아니라, 이 번지기 과정 자체가 묶기 작업이다("친구의 친구는 같은 그룹" 처리 포함).

```
결과 예 ("학생 영화"):
  클러스터 1: {s1, s4, ...}       — 학생 주인공 계열, 5개
  클러스터 2: {s2, ...}           — 관람 등급 계열, 3개
  클러스터 3: {s3, ...}           — 학교 배경 계열, 2개
```

### 4단계 — 엔트로피 계산

각 클러스터의 크기 비율을 "그 해석의 의도 확률"로 읽어 확률 분포를 만들고, 그 분포의 엔트로피를 u(x)로 삼는다.

```
분포: [5/10, 3/10, 2/10] = [0.5, 0.3, 0.2] → 엔트로피 높음 (해석이 갈림)
분포: [10/10] = [1.0]                       → 엔트로피 0   (전원 같은 해석)

u = -Σ p·log(p)
```

직관: 엔트로피는 "가상 사용자 한 명을 뽑았을 때 어느 해석 그룹 출신일지 맞히기 어려운 정도"다. 갈릴수록 높고, 만장일치면 0이다.

### 5단계 — 판정 분기 (OR 조건)

다음 두 조건 중 하나라도 참이면 재질문으로, 둘 다 거짓이면 원래 질문을 그대로 통과시킨다.

```
조건 1: u(x) > τ            (해석이 갈림 — 언어적 모호함)
조건 2: DB 매칭 ≥ 2건        (동명작 존재 — 데이터적 모호함)
```

OR로 결합하는 이유: 두 신호는 서로의 사각을 메운다. 시뮬레이션(조건 1)은 언어의 모호함을 잡지만 LLM의 지식에 의존한다 — 모델이 베테랑2(2024)의 존재를 모르면 샘플이 전부 2015년작으로 수렴해 놓친다. 메타데이터 매칭(조건 2)은 LLM 지식과 무관하게 동명작을 보장하지만 개체 유형만 커버한다.

τ는 배포 전에 모호/명확 라벨 검증셋(100~300개)으로 보정한다(예: 명확 질문의 95%가 통과하는 값). 운영 중에는 재질문율·오답 민원을 보며 조정하고, 트래픽 분포가 변하면 최근 N건 슬라이딩 윈도우 분위수로 동적 갱신할 수 있다.

### 6단계 — 선택지 조립

재질문의 선택지를 두 소스에서 모은다.

소스 A는 클러스터의 대표 문장이다(추가 생성 비용 0 — 판정의 부산물 재활용). 대표 선정은 클러스터 중심에 가장 가까운 샘플을 고르거나, LLM 1회로 짧은 명사구로 다듬는다(이것은 새 내용의 생성이 아니라 표현 정리 수준이다). 소스 B는 0단계의 DB 매칭 항목으로, 연도·감독 등 정확한 메타데이터 표기를 우선 채택한다.

병합·중복 제거 후 환각 검증을 거친다: 소스 A 출신 선택지 중 DB나 상식으로 근거를 확인할 수 없는 것(예: 존재하지 않는 "베테랑3")은 제거한다. 사용자가 근거 없는 선택지를 고르면 답할 수 없기 때문이다. 검증 후 선택지가 1개뿐이면 애초에 모호하지 않았던 것이므로 재질문을 취소하고 그 해석으로 통과시킨다.

형식은 CAmbigNQ 규격을 따른다: "어느 [카테고리]: [선택지1], [선택지2], ...?" 카테고리는 선택지 전체를 묶는 한 단어 요약("작품", "기준", "배우")이며, 묶을 수 없으면 "것"을 쓴다.

여기서 판정과 선택지의 기준을 분리한다는 점이 중요하다. 판정(4단계)은 클러스터의 "비율"을 쓴다 — 자연스러운 의도 쏠림("She's from Boston" 원리)이 반영되어야 하므로. 선택지 채택은 클러스터의 "존재"를 쓴다 — 10개 중 1개짜리 소수 클러스터도 선택지에는 포함해, 소수 의도의 사용자도 자기 보기를 볼 수 있게 한다.

```
완성 예:
"베테랑 줄거리" → "어느 작품 말씀이신가요: ① 2015년 베테랑  ② 2024년 베테랑2"
"학생 영화 추천" → "어떤 것을 원하세요: ① 학생이 주인공인 영화
                   ② 학생 관람가 영화  ③ 학교 배경 영화"
```

### 7단계 — 사용자 제시 (interrupt/resume)

에이전트 프레임워크의 중단점(interrupt) 기능으로 노드를 일시정지하고, 선택지를 버튼으로 렌더링하며, 반드시 자유 입력 폴백을 함께 둔다: "다른 의도라면 직접 입력해 주세요."

폴백이 필수인 이유: 1단계 샘플링이 다양성 부족으로 특정 해석을 누락했을 수 있고(예: "학생이 만든 영화" 해석), 그 의도의 사용자를 구제하는 마지막 안전망이 자유 입력이다. 사용자 응답이 선택지와 매칭되지 않으면 버리지 말고 그 텍스트 자체를 명확화 정보로 간주해 8단계로 보낸다.

### 8단계 — 최종 질문 재구성

원래 질문 x와 사용자의 선택(또는 자유 입력)을 합쳐, LLM 1회 호출로 자연스러운 한 문장의 명확한 질문으로 재작성한 뒤 다음 노드로 전달한다.

```
"베테랑 줄거리 알려줘" + "① 2015년 베테랑" 선택
→ "2015년 영화 베테랑의 줄거리 알려줘"

"학생 영화 추천해줘" + 자유 입력 "학생이 만든 독립영화요"
→ "학생이 제작한 독립영화 추천해줘"
```

재작성의 LLM 1회 비용은 사용자가 선택지를 고르는 대기 시간에 묻히므로 체감 지연이 없다.

## 4. 베이스라인 재질문 방식과 비교한 장점

### 4-1. vs "지시 한 줄" 방식 (시스템 프롬프트에 "모호하면 되물어라")

가장 먼저 떠올리게 되는 접근이지만, CLAM 실험에서 이 방식(Prompting baseline)은 37.5점으로, 구조화된 파이프라인(54.4점)에 크게 뒤졌다. 원인은 모델의 생성 관성이다: 학습 데이터에서 질문 다음에는 거의 항상 답이 왔으므로, 지시를 받아도 관성적으로 답을 생성해 버린다(실험에서 거의 되묻지 않음, AUROC 0.5 근처). RLHF를 거친 최신 모델은 "되묻기보다 넘겨짚는" 편향이 오히려 강하다는 후속 연구(ICLR 2025)도 있다. 본 설계는 판단을 모델에서 뺏어 코드(엔트로피 + τ 비교)로 옮겼으므로 이 편향의 영향을 받지 않으며, τ라는 손잡이로 재질문 빈도를 일관되게 제어·관측·튜닝할 수 있다.

### 4-2. vs "무조건 되묻기" 방식

모든 질문에 되물으면 모호한 질문의 정확도는 오르지만, 명확한 질문의 사용자를 매번 귀찮게 하고("극한직업 줄거리"에까지 되묻는 서비스는 버려진다), CLAM 실험에 따르면 불필요한 되묻기가 대화를 옆길로 새게 해 정확도 자체를 떨어뜨리는 경우도 있다. 본 설계는 명확한 질문을 추가 비용 거의 0으로 통과시키는 "선택성"을 갖는다.

### 4-3. vs 출력 기반 불확실성 방식 (Likelihood, Semantic Entropy)

"답을 여러 번 생성해 보고 갈리면 되묻는" 방식의 치명적 약점은, 모델이 답을 몰라서 환각으로 출력이 갈리는 경우(지식 부족)와 질문이 진짜 모호해서 갈리는 경우를 구분하지 못한다는 것이다. 전자에 되물어봤자 어차피 답을 모르므로 재질문이 낭비된다. 본 설계는 출력이 아니라 "해석"을 샘플링한다 — 지식 부족은 출력을 갈리게 할 수는 있어도 질문의 해석을 갈리게 하지는 못하므로("무명 선수 타율은?"의 뜻은 하나뿐), 가짜 모호함에 속지 않는다. Clarify When Necessary 논문에서 이 차이로 6개 설정 중 4개 최고 성능, 10% 예산에서 무작위 대비 2배 향상이 확인되었다.

또한 Agentic RAG에서는 비용 구조의 차이가 결정적이다. 출력 기반 방식은 판정을 위해 전체 검색·답변 파이프라인을 10번 완주해야 하지만, 해석 샘플링은 파이프라인을 전혀 돌리지 않는다("사용자가 뭘 물었는가"만 보면 되므로 검색도 hop도 불필요). 판정이 파이프라인과 완전히 분리되어 앞단 게이트로 배치 가능한 것이 본 설계의 구조적 핵심이다.

### 4-4. vs 학습 기반 방식 (전용 분류기/생성기 fine-tuning)

CAmbigNQ는 데이터셋 5,653개를 구축해 BART를 학습시켰으나 생성 F1 25.1에 그쳤고, 동시대의 175B GPT-3 fine-tuning 연구는 모호 입력의 44.5%를 인식하지 못했다. 학습 방식은 도메인·언어가 바뀌면 데이터셋부터 다시 만들어야 한다. 본 설계는 학습이 전혀 필요 없어(프롬프트 + 임베딩 + 코드) 영화 도메인 한국어 서비스에 즉시 적용되고, 프롬프트 수정만으로 반복 개선이 가능하다.

### 4-5. 재질문 자체의 품질: 선택지형 + 근거 보장

CAmbigNQ의 사람 선호도 실험에서, 되묻기(CQ) 방식은 "가능한 답 전부 나열"(DQ) 방식보다 다수(59% vs 33%)에게 선호되었고, 해석 개수가 많을수록 그 격차가 커졌다. 본 설계의 선택지는 모두 근거가 검증된 것만 제시된다: 소스 B(DB 항목)는 정의상 실재하고, 소스 A(클러스터 대표)는 "가상 사용자 중 실제로 그 해석을 한 사람이 있었다"는 검증을 통과한 것이며, 환각 검증으로 한 번 더 거른다. 또한 선택지들끼리 비슷해질 수 없다 — 클러스터가 나뉘었다는 것 자체가 동치 판정에서 "다른 뜻"으로 판명됐다는 증거이기 때문이다(비슷한 것은 이미 하나로 합쳐져 대표 하나만 나온다).

## 5. 원 논문 대비 변경 사항과 그 이유

### 변경 1 — greedy 초안 재질문 단계 삭제 → "의도 직접 샘플링"

원 논문(INTENT-SIM)은 먼저 되묻기 질문 q를 greedy로 1개 만들고, q에 대한 가상 답변 10개를 샘플링했다. 본 설계는 q 단계를 없애고 의도 자체를 직접 샘플링한다.

이유 1(프레이밍 오염): 가상 답변들은 전부 q에 조건화된다. q가 엉뚱한 축을 물으면("학생 영화"에 "어떤 장르요?") 답변 공간 전체가 그 축에 갇혀, 진짜 모호함이 안 보이거나(엔트로피 오판) 엉뚱한 것을 되묻게 된다. q는 측정 도구인 동시에 오염원이었다.

이유 2(축 고정의 전파): q를 최종 재질문 생성에서 빼더라도, 클러스터 자체가 q의 산물이므로 q의 축이 클러스터를 통해 그대로 전달된다. 오염원을 치우는 유일한 방법은 q 단계 자체의 제거다.

이유 3(비용): LLM 호출 1회 절약.

이론적 정당성: 원래 재려던 것은 의도 분포 P(y|x)의 엔트로피였고, q→답변 방식은 그것을 프록시(q)를 거쳐 간접 측정한 것이다. 직접 샘플링은 측정 대상을 프록시 없이 직접 재므로 프록시의 편향이 사라진다.

강점 보존 확인: 원 논문의 핵심 강점("지식 없음 + 해석 하나"인 가짜 모호함에 안 속는 것)의 원천은 q가 아니라 "출력이 아닌 해석 공간을 측정한다"는 원리다. 직접 샘플링도 같은 공간을 재므로 강점은 유지되며, 오히려 q가 이 강점을 흔들 수 있던 변수 하나였으므로 삭제로 더 안정화된다. 검증셋에 해당 유형 질문을 심어 실증 확인한다.

### 변경 2 — NLI 상호 함의 판정 → 한국어 임베딩 코사인 유사도

원 논문은 영어 DeBERTa-MNLI로 답변 쌍의 상호 함의를 판정했다. 본 설계는 임베딩 유사도를 쓴다. 이유: 한국어 환경이며, 비교 대상이 짧은 의도 문장/명사구("봉준호요")라 함의 추론보다 임베딩 유사도가 실용적이고 저렴하다. 간선을 만든 뒤 DFS로 묶는 구조는 동일하게 유지한다.

### 변경 3 — 예산 상위 b% 방식 → 임계값 τ 방식

원 논문은 평가를 위해 "전체 입력 중 점수 상위 b%에만 되묻기"를 썼다. 실시간 서비스는 입력이 하나씩 스트리밍으로 들어와 전체 분포를 모르므로 그대로 쓸 수 없다. 검증셋으로 오프라인 보정한 임계값 τ로 전환하며, 이는 CLAM이 실제로 채택한 방식(τ 튜닝)과도 일치한다. 논문의 AUROC가 좋다는 것은 어떤 τ를 골라도 순위가 좋다는 뜻이므로 이 전환은 정당하다.

### 변경 4 — CLAM의 재질문 생성 단계 삭제 → 클러스터 대표 직접 제시

초기 설계는 판정(INTENT-SIM) 후 CLAM 유도 문장("이 질문에 답하려면 다음의 명확화 질문을 해야 합니다:")으로 재질문을 별도 생성하는 것이었다. 최종 설계는 이 생성 단계를 없애고 판정부의 클러스터 대표를 그대로 선택지로 쓴다.

이유 1(축 불일치 위험): 판정은 클러스터의 갈림으로 했는데 재질문을 독립 생성하면 다른 축을 물을 수 있다(판정 근거는 "학생의 의미"인데 생성된 질문은 "어떤 장르요?"). 판정 근거와 제시물이 같은 재료에서 나와야 일관성이 보장된다.

이유 2(중복 제거): 같은 성격의 생성을 2회 하는 낭비를 없앤다. 클러스터로 살아남은 해석은 "실제로 그렇게 읽은 가상 사용자가 있었다"는 검증을 이미 통과했으므로, 별도의 품질 선별(예: 후보 재질문별 엔트로피 재측정)도 불필요하다 — 참고로 "답이 갈리는 재질문"이 좋은 재질문인 것은 아니므로(엉뚱한 축도 답은 갈린다), 엔트로피는 재질문 선별 기준으로 부적합하다.

CLAM에서 계승하는 것: 유도 문장이 아니라 구조다 — 판단을 별도 단계로 강제하는 파이프라인 설계(층위 2 프롬프트 엔지니어링), 그리고 정답을 아는 가상 사용자로 다중 턴을 자동 평가하는 프로토콜.

### 변경 5 — 자유형 재질문 → 선택지형 + 자유 입력 폴백

CLAM의 재질문은 자유형 문장이었다. 본 설계는 CAmbigNQ의 "어느 [카테고리]: [선택지들]?" 형식을 채택한다. 이유: CAmbigNQ의 사람 선호도 실험이 이 형식의 우위를 검증했고, 모바일에서 타이핑보다 탭이 압도적으로 편하며, 선택지가 있으면 응답 매칭·검증·재구성이 쉽다. 단 CAmbigNQ의 "선택지만 유효한 응답" 규칙은 평가용 단순화이므로 완화한다 — 실서비스에서는 샘플링이 누락한 해석의 사용자를 구제하기 위해 자유 입력 폴백을 반드시 함께 제공하고, 선택지 밖 응답도 명확화 정보로 활용한다.

### 변경 6 — 대화 이어붙이기 → 자연문 재작성

CLAM(Step 4)과 CAmbigNQ(3.3)는 원 질문 + 재질문 + 답변을 이어붙인 형태를 최종 입력으로 썼다. 본 설계는 LLM 1회로 자연스러운 한 문장으로 재작성한다. 이유: 뒤 단계가 임베딩 검색을 포함하는 RAG이기 때문이다. 이어붙인 문자열의 꼬리표는 검색 쿼리의 벡터를 오염시킬 수 있고, 모호한 질문의 오염은 multi-hop을 거치며 증폭된다. 깨끗한 자연문은 첫 hop 검색부터 정확하게 만든다. (참고: "고쳐 쓴 문장보다 대화 형태가 낫다"는 원 논문의 발견은 LLM에게 직접 입력할 때의 이야기이고, 여기서는 검색기에 입력하므로 사정이 다르다.)

### 변경 7 — DB 메타데이터 조회의 추가 (OR 판정 조건)

원 논문들에 없는 신규 추가. 이유: 의도 시뮬레이션은 LLM의 언어 지식에 의존하므로, 모델이 모르는 신작·동명작은 놓칠 수 있다(베테랑2를 모르면 샘플이 전부 원작으로 수렴). 제목/인물 필드의 매칭 건수는 LLM 지식과 무관한 확실한 신호이므로, 두 신호를 OR로 결합해 서로의 사각을 메운다. 언어적 모호함("학생 영화")은 시뮬레이션이, 데이터적 모호함("베테랑")은 메타데이터가 담당한다.

### 변경 8 — 판정 기준과 선택지 기준의 분리

원 논문에는 선택지 개념이 없어 해당 없음. 본 설계의 추가 규칙: 판정은 클러스터 비율(자연 의도 쏠림 반영 — 압도적으로 한쪽이면 되묻지 않는 것이 옳다), 선택지는 클러스터 존재(소수 해석의 사용자도 자기 보기를 봐야 한다). 같은 클러스터 정보를 두 용도에 다른 기준으로 쓰는 것이다.

## 6. 남은 리스크와 방어책

**리스크 1 — 사각지대 ④ (모호 + 지식/데이터 없음).** "모호하면서 되물어도 어차피 답할 수 없는" 질문은 재질문이 낭비된다. 이는 원 논문의 한계이기도 하다. 방어: DB 커버리지가 좁은 영역이 확인되면, 질문 임베딩과 DB 콘텐츠의 거리로 "답변 가능 영역인가"를 저렴하게 병행 추정하는 하이브리드를 검토한다.

**리스크 2 — 샘플 다양성 부족에 의한 해석 누락.** RLHF 모델(gpt-4o-mini)은 답이 한쪽으로 수렴하는 경향이 있어 소수 해석을 못 뽑을 수 있다. 방어: (a) 온도를 검증셋 AUROC로 튜닝, (b) "구별되는 의도" 나열 프롬프트로 전환 옵션, (c) 자유 입력 폴백, (d) DB 소스 B 병행 — 4중 방어.

**리스크 3 — 동치 판정기 오류.** 임베딩 임계값이 부적절하면 같은 뜻을 가르거나 다른 뜻을 합쳐 엔트로피가 왜곡된다. 방어: 검증셋에서 임계값을 함께 튜닝하고, 수동 샘플 검사로 클러스터 품질을 확인한다.

## 7. 검증 계획

**검증셋 — 이층 구조.** 1층: CLAM 방식으로 제조한 (모호, 명확) 쌍 — 명확한 실제 질문("2015년 베테랑 줄거리")을 규칙(대명사화 "그 영화 줄거리", 상위개념화 "베테랑 줄거리")으로 망가뜨려 쌍을 만든다. 저비용으로 기능의 기본 동작을 빠르게 확인한다. 2층: 실제 로그 기반 자연 질문 — 자연 발생 모호함은 더 미묘하므로 실전 성능은 이 층에서 측정한다. 추가로 "명확 + DB에 없는 대상" 유형 질문을 일부러 심어, 가짜 모호함 필터링(엔트로피가 낮게 나와 통과하는지)을 실증 확인한다.

**자동 테스트 — 특권 정보 오라클 (CLAM 프로토콜).** 각 쌍의 명확 버전을 특권 정보로 가진 가상 사용자 LLM을 만들어, 노드가 어떤 재질문/선택지를 내놓든 자동으로 응답하게 하고, 최종 재구성 질문이 명확 버전과 의도 일치하는지 채점한다. 가상 사용자 프롬프트에는 "두 후보 모두에 해당하는 답이 아니라, 한쪽만 특정하는 정보로 답하라"를 명시한다(CLAM의 CLAQUA I 실패 교훈: 동명 개체 구분 시 양쪽에 다 해당하는 정보를 주는 실수 방지). 프롬프트나 τ를 수정할 때마다 이 루프를 돌려 성능 회귀를 감지한다.

**지표.** (1) adjusted accuracy — 정답 1점/오답 0점에, 명확한 질문에 불필요하게 되물은 경우 λ를 곱해 감점(CLAM 방식). λ는 "불필요 재질문 1회의 UX 비용"으로 해석해 서비스 성격에 맞게 설정한다. (2) AUROC — 판정 점수 u(x)가 모호/명확을 얼마나 잘 가르는지, 온도·임베딩 임계값 튜닝의 기준. (3) 선택지 품질 — 예상 해석 집합과의 부분 일치(필요시 헝가리안 1:1 매칭, CAmbigNQ 방식). (4) 운영 지표 — 재질문율, 자유 입력 폴백 사용률(높으면 선택지 누락이 잦다는 신호).

## 9. 향후 개선 옵션 (병목 확인 후)

선택지 품질이 병목이면: "이중 턴 재랭킹" — 후보 선택지 구성을 2~3개 만들고, 각 구성에 대해 클러스터별 가상 사용자가 답했을 때 해석이 실제로 갈라지는지를 시뮬레이션해 가장 잘 가르는 구성을 채택한다(ICLR 2025 "Modeling Future Conversation Turns"의 채점 철학을 학습 없이 추론 시에 적용). 운영이 안정되면: 판정 로그로 소형 분류기를 증류해 게이트를 1회 호출로 경량화하고, 빈출 모호 패턴("감독 영화" 등)은 규칙/캐시로 처리한다.
